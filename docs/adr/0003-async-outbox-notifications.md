# ADR-0003：为什么通知使用异步 Outbox

## 决策

支付成功/发货等关键领域事件：与订单状态变更**同事务**写入 `outbox_events`，由 outbox worker 异步发布到通知/邮件，而不是事务提交后直接发通知。

## 原因

- 消除“提交成功但通知未发出”的窗口：事件与状态同事务，提交即保证可投递
- 进程崩溃后可补偿：worker 启动/定时补发未发布事件
- 幂等与死信：重复回调安全（processed_events），连续失败进 dead_events 停止重试并告警

## 权衡

- 多一次 outbox 表写入与 worker 消费延迟（秒级）；对通知场景可接受

## 状态

已接受。
