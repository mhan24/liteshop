# LiteShop × dujiao-next 功能对比与优化建议

**对比对象**：[dujiao-next/dujiao-next](https://github.com/dujiao-next/dujiao-next)（独角数卡 Go 重写版，v1.4.2，GPL-3.0）
**分析时间**：2026-08-04
**分析目的**：找出现有功能优化点 + 推荐新增功能，明确 LiteShop 的差异化定位

---

## 〇、定位差异（先说清楚）

| 维度 | LiteShop | dujiao-next |
|------|----------|-------------|
| 定位 | **轻量单机发卡站** | **多租户分销平台** |
| 支付 | BEpusdt（USDT 专一） | 10+ 网关（支付宝/微信/PayPal/Stripe/4 种 USDT…） |
| 用户体系 | 无（邮箱匿名下单） | 完整用户系统（注册/钱包/会员等级/2FA） |
| 部署 | 单二进制 + SQLite，零依赖 | 单二进制 + SQLite/PostgreSQL，可选 Redis |
| 前端 | Nuxt SSR（SEO 强） | 双 SPA（SEO 弱） |
| 许可证 | MIT | GPL-3.0 |
| 代码量 | ~6k 行 Go | 35 个模块，体量大数倍 |

**核心结论**：dujiao-next 走的是"大而全平台化"路线，LiteShop 应坚持"**小而美、5 分钟开店**"的差异化路线。**不建议照搬其重型功能**（分销/多租户/用户钱包），而应吸收其**轻量且高转化**的营销与安全细节。

---

## 一、现有功能优化建议（吸收对方优点）

### P0 — 高价值、低成本

#### 1. 优惠券系统（对方核心营销能力）
**对方**：固定金额/百分比券、按数量抵扣、会员等级限制、批发价商品禁券。
**现状**：LiteShop 无任何促销手段，价格只能改商品原价。
**建议**（轻量版）：
- `coupons` 表：券码、类型（固定/百分比）、面额、有效期、使用次数上限、适用商品
- 下单 API 增加 `coupon_code` 参数，服务端验券 → 折后价创建 BEpusdt 交易
- 管理后台：券 CRUD + 使用记录
- **工作量**：~1 天 | **转化提升**：高（可发券做社群营销）

#### 2. 批发价 / 阶梯价
**对方**：按 SKU 设置阶梯价（买 10 件单价 9 折）。
**现状**：LiteShop 只有单一 `price_cents`。
**建议**（轻量版）：
- 商品表加 `wholesale_json`：`[{"min_qty":5,"discount":0.95},{"min_qty":10,"discount":0.9}]`
- 下单时按数量匹配折扣，前台展示阶梯价格表
- **工作量**：~半天 | 与优惠券互斥规则可选

#### 3. 支付回调地址自定义/隐藏
**对方**：5 条可自定义回调路径，防止回调伪造和路径枚举扫描。
**现状**：LiteShop 回调固定 `/notify/bepusdt`，扫描器可轻易识别建站程序并尝试伪造回调（虽有验签，但暴露攻击面）。
**建议**：
- `settings` 加 `bepusdt_notify_path`，默认随机生成（如 `/notify/x7k2p9`）
- 初始化时展示给管理员配置到 BEpusdt
- **工作量**：~1 小时 | **安全提升**：中

#### 4. 商品成本价 + 利润统计
**对方**：商品有 `cost_price`，仪表盘显示利润。
**现状**：LiteShop 只统计营收，不知毛利。
**建议**：
- 商品加 `cost_cents`（仅 admin 可见）
- 仪表盘加"今日毛利 = 营收 - 已售卡密成本"
- **工作量**：~2 小时

#### 5. 库存显示模糊化
**对方**：可开启"模糊库存"（前台显示"有货/紧张"而非精确数字，防同行探库存）。
**建议**：站点设置加 `stock_display_mode`：`exact | fuzzy`（>10 显示"充足"，1-10 显示"紧张"，0 显示"售罄"）。
- **工作量**：~1 小时

### P1 — 中价值

#### 6. TOTP 双因素认证（后台）
**对方**：管理员和用户均有 TOTP 2FA。
**现状**：LiteShop 后台仅密码，撞库/泄露即失守。
**建议**：管理员账号加 TOTP（`pquerna/otp` 纯 Go 库），登录时二步验证，后台"账号"页扫码绑定。
- **工作量**：~半天 | **安全提升**：高

#### 7. 卡密导入去重开关
**对方**：导入卡密可选"去重/允许重复"（循环卡密场景）。
**现状**：LiteShop 导入不做去重检查，重复卡密会重复售卖。
**建议**：导入时加 `ON CONFLICT` 去重选项 + 导入结果反馈（新增 X 条 / 跳过重复 Y 条）。
- **工作量**：~2 小时

#### 8. 商品限购（最小/最大购买量）
**对方**：按商品设最小购买量。
**建议**：商品加 `min_qty`/`max_qty`，下单校验。当前 `apiCreateOrder` 只硬性 cap 100，应改为读商品配置。
- **工作量**：~1 小时

#### 9. 后台一键升级
**对方**：后台可从 GitHub Releases 一键拉取新二进制自升级（带回滚保护）。
**建议**（简化版）：系统页显示当前版本 + 检查 GitHub latest release 提示更新；自升级可选做。
- **工作量**：提示 ~1 小时；自升级 ~1 天（风险高，谨慎）

#### 10. 邮件群发 / 订单买家通知
**对方**：Telegram 广播、按订单筛选发邮件。
**建议**：订单页加"向选中订单买家重发/补发邮件"批量操作（已有 SMTP 基建，边际成本低）。
- **工作量**：~半天

## 二、推荐新增功能（差异化方向）

### A. 营销转化类（优先做）

1. **优惠券**（见上 P0-1）
2. **批发价**（见上 P0-2）
3. **订单找回增强**：当前仅邮箱查单；可加"邮箱 + 订单号"或"查单验证码邮件"（防他人用邮箱枚举订单）
4. **首页公告弹窗**：对方有公共弹窗；LiteShop 已有公告栏，加"每次访问弹一次（localStorage 记忆）"即可
5. **友链/导航增强**：已有友链，可加后台可配置的顶部快捷按钮

### B. 安全合规类

6. **支付回调路径自定义**（见上 P0-3）
7. **后台 TOTP 2FA**（见上 P1-6）
8. **管理后台路径自定义**（对方 `web.admin_path` 可改，防默认路径扫描）
9. **登录审计用户可见**（对方用户可见自己登录日志；LiteShop 可先在 audit_logs 增加登录事件）

### C. 数据运营类

10. **销售报表**：按日/周/月营收曲线（ECharts），按商品占比饼图（驾驶舱已有点位数据，只差图表）
11. **卡密导出**：对方支持卡密 CSV 导出（LiteShop 已有订单导出，卡密导出对称补齐）
12. **Webhook 出站增强**：已有 webhook 通知，可加**签名头**（`X-LiteShop-Signature: HMAC(body, secret)`），让接收方可验真伪

### D. 不建议做的（对方有，但不符合 LiteShop 定位）

| 功能 | 不做原因 |
|------|----------|
| 用户注册/钱包/余额 | 与"匿名邮箱下单"的极简定位冲突，引入账户体系=引入安全/合规/客服成本 |
| 多租户分销（reseller） | 复杂度爆炸（域名/分润/提现），目标用户不需要 |
| 上下游 API  federation | 需要生态，单店场景无价值 |
| 多支付网关（支付宝/微信等） | 需要企业资质/备案，目标用户就是冲 USDT 来的 |
| Casbin RBAC | 现有 3 级角色已够用 |
| PostgreSQL | SQLite 正是卖点 |

## 三、优先级路线图（建议）

| 阶段 | 内容 | 预期效果 |
|------|------|----------|
| **v1.1 营销包** | 优惠券 + 批发价 + 限购 | 转化率提升，可跑促销活动 |
| **v1.2 安全包** | 回调路径自定义 + TOTP 2FA + admin 路径自定义 | 防扫描/防伪造/防撞库 |
| **v1.3 运营包** | 成本价/毛利 + 销售曲线图 + 卡密导出/去重 + 批量重发邮件 | 日常运营提效 |
| **v1.4 打磨** | 库存模糊化 + 公告弹窗 + webhook 签名 + 版本检查 | 细节体验 |

---

## 四、一句话总结

> dujiao-next 是"平台操作系统"，LiteShop 是"开箱即用的自动售货机"。
> 抄它的**优惠券、批发价、回调隐藏、TOTP、成本价**这五个轻量高价值功能，
> 坚决不碰它的**用户体系、钱包、分销、多网关**这四个复杂度黑洞。
