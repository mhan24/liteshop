## 技术选型
Next.js（App Router）+ TypeScript + Tailwind + shadcn/ui；Drizzle ORM + SQLite（better-sqlite3）；HMAC 签名 HttpOnly cookie 会话；Docker 多阶段构建（node:20-alpine，standalone）+ docker-compose。

## 数据模型（Drizzle，迁移全部 additive，禁改历史迁移）
- **products**：name/slug/description/image_url/price(分)/currency(默认CNY)/extra(JSON)/delivery_type(auto|manual)/stock_limit/status/sort
- **cards**：product_id/content/status/**order_id**/sold_at
  - **CardStatus = "available" | "reserved" | "sold"**：available --fulfill--> reserved（占卡，写入 order_id）--成功--> sold（落 sold_at）；发货失败/关单 → reserved 释放回 available
  - **UNIQUE(product_id, content)**：DB 层拒绝重复导入（代码去重仅前置）
- **orders**：
  - **order_no 非自增**：`LS + YYYYMMDD + 8 位随机(base32) + 2 位校验和`（如 LS2026101112345678A9），唯一索引+冲突重试，不暴露销量
  - 商品快照/quantity/total/email/delivery_content/trade_id/expected_actual_amount/expiration_time/block_txn_id/paid_at
  - **OrderStatus = "pending" | "paid" | "delivering" | "completed" | "expired" | "closed"**：paid=已支付待处理；delivering=自动发货进行中（占卡中/卡池空待补/临时失败，后台可补卡重试或人工录入→completed）
- **settings**：仅站点级（site_name/site_url 等）
- **payment_configs**：**provider / enabled / config_json**（bepusdt 的 api_base/token/trade_type/timeout 存 config_json；未来 stripe/paypal/alipay 加行不改表）
- **admin_logs**（审计）；**notify_logs**（原始报文 + **payload_hash=sha256(raw_body)** 索引，识别重复通知/重放）

## 风险对策
① 并发：领卡条件原子 UPDATE…WHERE status='available'…RETURNING（受影响行数判库存，不超卖）；发货在 better-sqlite3 IMMEDIATE 事务内（状态机守卫→占卡→确认/释放→提交）；manual 库存条件扣减；单写者+compose 单副本；并发单测 10 回调仅发 1 卡
② 金额防篡改：履约只信服务器间回调；timingSafeEqual 验签→trade_id 对快照→**amount/actual_amount 经 toCents() 字符串解析转 BigInt 分比较（禁浮点运算）**→status=2 才入账；报文+payload_hash 落 notify_logs
③ 后台安全：ADMIN_PASSWORD_HASH(scrypt)+hash-password 脚本；HMAC 会话（HttpOnly/SameSite/Secure、8h、session_version）；CSRF+Origin 校验；登录限速 5 次锁 15 分钟；middleware 守护 /admin/*；安全响应头；admin_logs；README 强制 HTTPS
④ Docker：builder 装 python3/make/g++ 编译 better-sqlite3、固定 node:20-alpine 具体版本+`npm ci && npm rebuild better-sqlite3`（防 invalid ELF header，README 写升级流程）；启动 PRAGMA（WAL/NORMAL/busy_timeout/foreign_keys）；named volume+healthcheck；`npm run backup`(VACUUM INTO)；非 root
⑤ bepusdt（源码级核实）：回调 trade_id/order_id/token/block_transaction_id/signature=string、amount=float64、actual_amount=string、status=int(1/2/3)；应答 200+`success`；签名=剔除 signature→空值跳过→键字典序→`k=v&`（Go %v 格式化）→+Token→MD5 小写（单测对齐官方 PHP SDK）；创建交易 POST /api/v1/order/create-transaction；trade_type 全清单入配置
⑥ 扩展性：currency+extra(JSON)；PaymentProvider/DeliveryStrategy 双接口；additive 迁移；payment_configs 拆表

## Implementation Notes
- 所有金额内部使用整数分（BigInt），边界处经 toCents() 转换
- 所有状态使用 TypeScript string union（OrderStatus/CardStatus）
- 所有数据库迁移必须 additive，禁止直接修改历史 migration

## Engineering Constraints
- 页面层只负责 UI 与输入输出
- 所有业务逻辑必须位于 src/server
- 所有数据库写操作必须经过 service 层
- 禁止 API Route 直接操作数据库
- 所有支付渠道必须实现 PaymentProvider 接口
- 所有发货方式必须实现 DeliveryStrategy 接口
- 所有订单状态变化必须经过状态机校验
- 禁止硬删除已产生交易关联的数据

## 页面与流程
前台（游客）：`/` bento 商品网格 → `/products/[slug]` 详情+购买表单（邮箱必填/数量/备注、显示余量）→ payment_url → `/pay/return` 轮询展示；`/orders` 订单号+邮箱双因子查单。
后台：登录、仪表盘（订单/销售额/待发货含 delivering/卡密预警）、商品管理、卡密管理（批量导入、余量已售、删除未用）、订单管理（筛选搜索、人工发货、重试发货、补发卡密、关闭）、设置（站点 + 支付渠道配置）。
设计规范：taste-skill · minimalist-ui（Geist Sans/Instrument Serif/Geist Mono；#F7F6F3/#EAEAEA/#111111；粉彩徽章；Phosphor 图标；bento 网格；py-24；IntersectionObserver 入场动效；禁 emoji/占位文案）。
